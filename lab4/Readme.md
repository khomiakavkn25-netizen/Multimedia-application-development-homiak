# Лабораторна робота 4. Предиктори PNG

**Дисципліна:** Розробка мультимедійних застосунків  
**Спеціальність:** 122 Комп'ютерні науки, група КН-3/1  
**Мова та бібліотеки:** Python, NumPy, Pillow

## Мета роботи

Реалізувати фільтри PNG (None, Sub, Up), виміряти, як вони змінюють ентропію зображень, написати зворотне перетворення й переконатися, що дані відновлюються без втрат, а також реалізувати адаптивний вибір фільтра для кожного рядка.

## Хід роботи

### Завдання 1. Фільтрація одного рядка

Я написав функцію `filter_row(cur, prev, f)`. Лівий сусід утворюється зсувом рядка на одну позицію праворуч із нулем на початку, верхній сусід беремо з попереднього рядка. Для першого рядка попередній рядок складається з нулів. Різницю рахував за модулем 256: `(cur - pred) % 256`.

Перевірка на рядку з рисунка 2 дала очікувані результати:

```
Sub:  [40  2  2  2  2  2  2  2]
None: [40 42 44 46 48 50 52 54]
Up (cur == prev): [0 0 0 0 0 0 0 0]
```

### Завдання 2. Фільтрація зображення та ентропія

Функція `filter_image(img, f)` застосовує фільтр до кожного рядка. Попереднім рядком для предиктора я брав вихідний рядок `img[y]`, а не відфільтрований. Ентропію рахував за гістограмою (функція `entropy` з лабораторної 3).

Використані зображення: градієнт і білий шум (генеруються кодом, 512×384), скріншот (кадр, 299×225) і фотографія (960×1280). Скріншот і фотографію я перевів у відтінки сірого.

**Таблиця 1. Ентропія, біт на піксель**

| Зображення | До | None | Sub | Up |
|---|---|---|---|---|
| Градієнт | 8,00 | 8,00 | 1,00 | 0,05 |
| Білий шум | 8,00 | 8,00 | 8,00 | 8,00 |
| Скріншот | 7,75 | 7,75 | 6,46 | 6,64 |
| Фотографія | 7,47 | 7,47 | 3,88 | 3,91 |

Колонка None збігається з колонкою «До», бо цей фільтр нічого не змінює. Для градієнта Up дав 0,05 біта, тому що всі його рядки однакові, і різниця з верхнім рядком скрізь дорівнює нулю (ненульовий лише найперший рядок).

### Завдання 3. Зворотне перетворення

Я написав `unfilter_row` та `unfilter_image`. Під час відновлення лівий сусід беремо з рядка, який відновлюється зараз, тому пікселі обходяться циклом. Верхній сусід береться з уже відновленого попереднього рядка. Відновлення йде за модулем 256: `(enc + pred) % 256`.

Для всіх чотирьох зображень і всіх трьох фільтрів `np.array_equal(img, back)` дало `True`, тобто зображення відновлюється байт у байт.

### Завдання 4. Адаптивний вибір фільтра для рядка

Функція `filter_adaptive` для кожного рядка пробує три фільтри, рахує суму модулів за функцією `sum_abs` (значення більші за 127 переводяться у від'ємні відніманням 256) і обирає фільтр із найменшою сумою. Номери обраних фільтрів зберігаються для відновлення. Адаптивний результат також відновлюється без втрат (`True` для всіх зображень).

Розподіл обраних фільтрів:

| Зображення | None | Sub | Up |
|---|---|---|---|
| Градієнт | 0 | 1 | 383 |
| Білий шум | 122 | 130 | 132 |
| Скріншот | 0 | 136 | 89 |
| Фотографія | 0 | 541 | 739 |

### Завдання 5. Підсумкова таблиця

**Таблиця 2. Підсумок (адаптивний вибір)**

| Тип зображення | Оптимальний фільтр (рядків) | Ентропія до / після | Виграш, % |
|---|---|---|---|
| Градієнт | Up (383 з 384) | 8,00 / 0,01 | 99,8 |
| Білий шум | хаотично (Up 132, Sub 130, None 122) | 8,00 / 8,00 | 0,0 |
| Скріншот | Sub (136 з 225), Up (89) | 7,75 / 6,37 | 17,8 |
| Фотографія | Up (739 з 1280), Sub (541) | 7,47 / 3,75 | 49,8 |

Для градієнта виграш майже стовідсотковий, бо всі його рядки однакові й різниця з верхнім сусідом дорівнює нулю. Для білого шуму виграш нульовий: сусідні пікселі не пов'язані між собою, тому віднімання нічого не дає, а вибір фільтра випадковий. Фотографія має великі плавні області, де сусіди схожі, тому виграш близько 50%, але дрібна текстура й шум не дають різницям стати нульовими. Мій «скріншот» виявився кадром із відео зі стисненням, тому він шумний і дає лише 18%: різниці між сусідами лишаються помітними. Ентропія за гістограмою не була справжньою межею, бо вона не бачить зв'язків між сусідніми пікселями, а фільтр їх використовує.

## Додатково

Зберігання номера фільтра коштує 1 байт на рядок. Для фотографії висотою 1280 рядків це 1280 байт, приблизно 0,1% від розміру зображення, тобто дуже мало.
